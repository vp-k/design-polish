> 이 문서는 **제품의 성격**을 정의한다. 색을 몇 개 쓰는지가 아니라, 왜 그 색인지를 적는다.

> ⚠️ **이 문서가 틀리면 결과물은 "일관되게 틀린" 디자인이 된다.** 값보다 이 문서의 검토에 시간을 쓸 것.

## 0. 출처 표기 규칙 (필수)

각 결정에는 출처를 붙인다. **브랜드 정체성(1절)은 `assumption` 금지** — 추측으로 정한 성격은
전 화면에 일관되게 전파되어 되돌리기가 가장 비싸다.

| 마커 | 의미 |
|------|------|
| `user-fact` | 사용자가 직접 말한 것 |
| `repo-fact:<path>` | 기존 코드/에셋에서 확인한 것 (경로 명시) |
| `assumption: <근거>` | 추론. 근거를 반드시 함께 적는다 |
| `blocker` | 확인 없이는 진행 불가. 미해결 blocker가 있으면 계약을 확정하지 않는다 |

## 1. 제품 성격 (Product Character)

> `user-fact` 또는 `blocker`만 허용. 모르면 묻는다.

- **한 문장 정의**: <이 제품은 ___한 사람에게 ___한 인상을 주어야 한다> `user-fact`
- **타겟 사용자**: <> `user-fact`
- **경쟁 대비 포지션**: <> `user-fact`
- **톤 스펙트럼** (해당 위치에 표시):
  - 신뢰 ←──●───→ 대담
  - 절제 ←───●──→ 화려
  - 친근 ←─●────→ 전문
- **하지 말아야 할 인상**: <예: 장난스러움, 저가 느낌> `user-fact`

## 2. 디자인 원칙 (Design Principles)

각 원칙은 **버릴 것을 명시**해야 한다. 무엇도 포기하지 않는 원칙은 원칙이 아니다.

| DD-001 | <예: 정보 밀도 > 여백의 미> | 첫인상의 여유로움 | `user-fact` |

## 4. 컴포넌트 계약 (Component Contract)

컴포넌트는 default 하나가 아니라 **상태의 집합**이다. 각 상태의 표현을 결정 ID로 못 박는다.

| 컴포넌트 | default | hover | active | focus | disabled | loading | 빈/에러 |
|----------|---------|-------|--------|-------|----------|---------|---------|
| Button (primary) | DD-009 | 8% darken | scale .98 | 2px ring, offset 2 | opacity .5 + `cursor:not-allowed` | 스피너 + 비활성 | — |
| Input | | | | | | | 에러 문구는 필드 하단 |
| Card | | | | | | 스켈레톤 | 빈 상태 문구 필수 |

> focus는 **반드시** 시각 변화가 있어야 한다 (DP-S002, WCAG 2.4.7).
> disabled는 opacity만으로 표현하지 않는다 (DP-S001).

## 5. 레이아웃 문법 (Layout Grammar)

- **그리드**: <12col / max-width 1200px / gutter 24px> — DD-0NN
- **섹션 리듬**: <상하 여백 64px, 모바일 40px> — DD-0NN
- **정렬 원칙**: <좌측 정렬 기본. 중앙 정렬은 히어로 1회로 제한>
- **반응형 분기**: <375 / 768 / 1440>

## 6. 한국어 타이포그래피 (해당 시)

- 폰트 스택에 한국어 폰트를 **명시**한다 (`Inter, serif` 같은 스택은 한글만 명조로 떨어진다 — DP-K001)
- 긴 문단은 `word-break: keep-all` (DP-K002)
- 자간은 -2% 미만으로 줄이지 않는다 (DP-K003)
